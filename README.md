# RefBoard — 케이스 스터디 & 레퍼런스 정리 프로그램

매번 케이스와 레퍼런스를 새로 찾고 PPT에 붙이는 일을 줄이기 위한 도구입니다.

1. **모으기**: 핀터레스트 핀·보드, 웹페이지, 이미지 링크를 붙여넣고 **키워드(태그)**와 함께 저장합니다. 이미지는 따로 저장하지 않고 원본 링크로 연결합니다.
2. **찾기**: 키워드를 넣으면 관련도 순으로 **자동 정렬**하고 태그별로 묶어서 보여줍니다.
3. **문서 만들기**: 키워드 하나로 **태그·케이스별 그룹 → 페이지 → 레이아웃**까지 자동으로 구성합니다. 그리드(N단) 배치와 이미지 비율에 맞춘 자유 배치 중에서 고를 수 있습니다.
4. **다듬기**: AI(Claude)가 페이지마다 타이틀·태그라인·설명·캡션을 제안합니다. 폰트·크기·자간·행간을 세밀하게 조정할 수 있고, 프레젠테이션 도구처럼 요소를 옮기고 정렬할 수 있습니다.
5. **출력**: PDF(인쇄), PowerPoint, 단일 HTML 파일로 내보내거나 웹 뷰어·발표 모드로 바로 볼 수 있습니다.
6. **팀 작업 (웹 서비스)**: 메일 가입·로그인(카카오·네이버 선택), 팀 프로젝트로 라이브러리와 문서를 공유하고, 초대한 사람과 **동시에 편집**합니다. 누가 언제 무엇을 추가·수정했는지 기록이 남습니다.

기본 페이지 양식은 첨부된 **A4 보고서 템플릿(A4_Template_New.pdf)** 을 치수 그대로 재현합니다.

- **그리드**: A4 가로, 좌우 여백 10mm, **5단 · 단 간격 3mm**. 헤더는 13mm에서 시작하고 이미지 영역은 34.5mm~198mm.
- **헤더**: Title 17/21pt (1단) | Sub-Title 12/16pt (2단) | 설명 10/17pt (3~5단). 글꼴은 Poppins + Pretendard, 먹색 `#231f20`.
- **글 배치(짧은 글 / 긴 글)**: 설명이 3줄 안이면 제목 옆(3~5단)에 두고 이미지는 전체 폭에, 길면 왼쪽 1단으로 내려가고 이미지는 2~5단으로 좁아집니다. 자동으로 고르거나 직접 정할 수 있습니다.
- **표지**: 가운데 `TITLE`(SemiBold 14.5pt, 대문자) + `PRESENTED BY 부서명`(ExtraLight 8pt). 제목은 문서 제목, 부서명은 팀 기본 설정과 자동으로 연결됩니다(`{title}`, `{dept}`).
- **간지**: 가운데 제목(Medium 14pt) + 한 줄 설명(ExtraLight 10.5pt).
- **하단 양식**: 왼쪽 부서명(기본 `OO TEAM`), 오른쪽 문서명 + 페이지 번호(번호만 한 단계 굵게), Poppins Light 5.5pt. 팀 기본 설정에서 부서명·양식을 한 번만 정해 두면 새 문서에 자동으로 들어갑니다.

처음 쓰는 사람은 상단의 **💡 TIP** 버튼(사용 가이드)에서 핀터레스트 링크 복사법부터 문서 만들기, 오토 레이아웃, 팀 초대까지 스타디움 예시로 순서대로 볼 수 있습니다. 로그인 전에도 `#/guide` 로 열립니다.

## 실행

### 가장 쉬운 방법: 더블클릭 실행

1. 코드를 내려받습니다.
   - GitHub에서 `claude/case-study-reference-organizer-407bdl` 브랜치를 연 뒤 **Code → Download ZIP**을 누르고 압축을 풉니다.
   - 또는 `git clone -b claude/case-study-reference-organizer-407bdl https://github.com/cokean89-sudo/test01.git refboard`
2. 폴더 안의 실행 파일을 더블클릭합니다.
   - **Mac**: `start-mac.command`. 처음에 "확인되지 않은 개발자" 경고가 뜨면 파일을 **우클릭 → 열기**를 누릅니다.
   - **Windows**: `start-windows.bat`
3. 처음 한 번은 Node.js(없을 때)와 필요한 패키지를 설치합니다(1~2분). 준비되면 브라우저가 **http://127.0.0.1:5178** 을 엽니다.
   - 처음 열면 **회원가입** 화면이 나옵니다. 메일 서버를 설정하지 않은 개인 실행에서는 인증 링크가 화면에 바로 표시되니 눌러서 가입을 마치세요.
   - Mac은 Homebrew가 있으면 자동으로 설치하고, 없으면 nodejs.org 설치 페이지를 엽니다.
   - Windows는 winget으로 설치합니다. 설치가 끝나면 실행 파일을 한 번 더 더블클릭하세요.
4. 끝낼 때는 열린 터미널 창에서 `Ctrl+C`를 누르거나 창을 닫습니다. 데이터는 `data/refboard.sqlite`에 남습니다. 이전 버전의 `data/db.json`이 있으면 처음 가입한 사람의 개인 공간으로 자동으로 옮겨집니다.

### 터미널로 실행

Node.js 22.13 이상이 필요합니다(내장 SQLite 사용).

```bash
npm install
cp .env.example .env       # (선택) ANTHROPIC_API_KEY 입력
npm run app                # 빌드 후 실행 + 브라우저 열기 → http://127.0.0.1:5178
```

가입 후 라이브러리가 비어 있으면 세 단계 안내(링크 붙여넣기 → 키워드 달기 → 문서로 만들기)와 **레퍼런스 추가하기 / 사용 가이드 보기** 버튼이 보입니다.

| 명령 | 설명 |
| --- | --- |
| `npm run app` | 빌드 + 실행 + 브라우저 열기 (일반 사용) |
| `npm run dev` | 개발 서버 (코드 수정 시 자동 반영) |
| `npm run build` / `npm start` | 프로덕션 빌드 / 실행 |
| `npm test` | 단위 테스트 + 서버 통합 테스트(가입·로그인·권한·초대·중복·동시 편집) |
| `npm run typecheck` | 타입 검사 |
| `npm run backup` | 데이터베이스 백업 (`data/backups/`, 서버가 켜져 있어도 됨) |

## 계정과 팀

### 가입·로그인

- **메일 가입**: 이름·메일·비밀번호로 가입하고 메일의 인증 링크(24시간 유효)를 눌러야 로그인할 수 있습니다. 비밀번호는 10자 이상, 영문 대/소문자·숫자·특수문자 중 두 종류 이상이어야 하며, 흔한 비밀번호나 메일 아이디가 들어간 비밀번호는 거절합니다.
- **비밀번호 찾기**: 메일로 재설정 링크(1시간, 1회용)를 보냅니다. 재설정하면 다른 기기의 로그인은 모두 끊깁니다.
- **로그인 화면**
  - `로그인 상태 유지`: 끄면(기본) 브라우저를 닫을 때 로그아웃되는 세션 쿠키로 로그인하고, 서버에서도 12시간 무활동·최대 1일이면 만료됩니다. 켜면 `SESSION_MAX_DAYS`(기본 30일)까지 유지됩니다. 카카오·네이버 로그인에도 같은 선택이 적용됩니다. 공용 PC에서는 끄라는 안내가 함께 보입니다.
  - `아이디 기억하기`: **메일 주소만** 이 브라우저에 저장합니다(비밀번호는 저장하지 않음). 체크를 해제하면 바로 지웁니다.
  - 비밀번호 보기 토글, Caps Lock 켜짐 경고, Enter 로 로그인, 이해하기 쉬운 오류 문구. 로그인이 필요한 주소로 들어왔다면 로그인 후 그 화면으로 돌아갑니다.
  - 카카오·네이버 버튼은 각 사 로그인 버튼 가이드(컨테이너 색·심볼·문구)에 맞췄고, 메일 로그인 버튼과 높이·모서리·간격을 통일했습니다. 공식 심볼 파일을 `public/brand/`에 넣으면 그 파일을 씁니다([`public/brand/README.md`](public/brand/README.md)).
- **카카오 / 네이버 로그인**: 가능합니다. 각 개발자 센터에 앱을 등록하고 키를 `.env`에 넣으면 로그인 화면에 버튼이 나타납니다(아래 [소셜 로그인 설정](#소셜-로그인-설정-카카오--네이버)). 이미 메일로 가입한 사람은 **내 계정 → 소셜 로그인 연결**에서 카카오·네이버를 연결할 수 있습니다.
- **내 계정**: 이름·비밀번호 변경, 카카오·네이버 연결, **다른 기기 모두 로그아웃**(공용 PC에서 로그아웃을 잊었을 때).

### 팀 프로젝트

- 가입하면 **개인 공간**이 생기고, `팀 만들기`로 팀 프로젝트를 추가합니다. 사이드바 상단에서 공간을 전환합니다. 레퍼런스·케이스·문서는 공간(팀)별로 따로 관리됩니다.
- **역할**

  | 역할 | 할 수 있는 일 |
  | --- | --- |
  | 소유자 | 모든 권한 + 팀 삭제, 다른 멤버를 소유자·관리자로 지정 |
  | 관리자 | 멤버 초대·역할 변경(편집자·뷰어)·내보내기, 팀 기본 설정, 팀 백업 |
  | 편집자 | 레퍼런스·케이스·문서 추가와 편집 |
  | 뷰어 | 보기, 웹 뷰어·발표, 내보내기(PDF·PPTX·HTML) |

- **초대는 비공개 방식만** 지원합니다(공개 링크 없음). 관리자 이상이 `팀 설정 → 초대`에서 만듭니다.
  - **메일 초대**: 받는 사람 메일 주소에 묶인 초대 링크를 보냅니다(7일, 1회용). 같은 메일로 로그인한 사람만 수락할 수 있어, 링크가 새어 나가도 다른 사람은 들어올 수 없습니다.
  - **초대 코드 + 비밀번호**: `ABCDE-FGHJK` 형식의 코드와 관리자가 정한 비밀번호를 따로 전달합니다. 유효기간(1~30일)과 사용 횟수를 정할 수 있고, 비밀번호를 10번 틀리면 코드가 잠깁니다. 비밀번호는 해시로만 저장합니다.
  - 초대받은 사람은 가입·로그인 후 `팀 참여하기`에서 코드와 비밀번호를 넣습니다. 초대는 언제든 취소할 수 있습니다.
- **팀 기본 설정**: 팀에서 새 문서를 만들 때 자동으로 들어갈 값 — 부서명(하단 왼쪽), 하단 가운데·오른쪽 문구(`{title}` = 문서 제목), 페이지 번호 위치·형식, 페이지 크기, 강조색, 타이포 프리셋, AI 작성 언어·글쓰기 관점·문체. 팀을 처음 만들면 이 화면이 먼저 열립니다. 문서마다 따로 바꿀 수 있습니다.
- **활동 기록**: 누가 언제 레퍼런스를 추가·수정·삭제했는지, 문서를 만들고 고쳤는지, 멤버·초대 변경을 팀 설정의 `활동` 탭에서 볼 수 있습니다.

### 중복 이미지

- 같은 이미지를 다시 추가하면 **"중복"** 표시와 함께 **누가, 언제 추가했는지** 보여줍니다. 주소가 조금 달라도(핀터레스트 해상도 경로 `236x`/`originals`, `utm_` 같은 추적 파라미터, `http`/`https`) 같은 이미지로 판단합니다.
- 중복이어도 새로 만들지 않고 기존 항목에 **태그를 합치고**, 제목·메모 등 내용은 그대로 편집할 수 있습니다. 레퍼런스 상세에는 처음 추가한 사람과 마지막으로 수정한 사람이 표시됩니다.

### 동시 편집

- 같은 문서를 여러 명이 동시에 열 수 있습니다. 상단에 **지금 보고 있는 사람**과 각자 보고 있는 페이지가 표시됩니다.
- 편집 내용은 자동 저장되고 다른 사람 화면에 바로 반영됩니다. 서로 다른 요소·페이지를 고친 경우 **양쪽 수정이 모두 합쳐집니다.** 같은 요소의 같은 속성을 동시에 고친 경우에만 나중 저장이 이기고, 그 사실을 알려줍니다.
- 라이브러리(레퍼런스·케이스) 변경도 실시간으로 팀원 화면에 반영됩니다.
- **버전 기록**: 편집기의 `버전 기록`에서 저장 시점별(같은 사람이 10분 안에 이어서 저장한 것은 하나로) 작성자와 페이지 미리보기를 보고, 이전 버전으로 복원할 수 있습니다. 복원도 새 버전으로 남습니다.
- 뷰어 역할은 편집기에서 읽기 전용으로 열립니다.

## 사용 흐름

### 1. 레퍼런스 추가 — `레퍼런스 추가`

- **핀터레스트 링크 복사**: 핀을 열고 **공유 → 링크 복사**(앱도 같음), 또는 이미지 위에서 **우클릭 → 이미지 주소 복사**. 자세한 그림 설명은 TIP 가이드 1단계에 있습니다.
- 링크를 여러 개 붙여넣으면(줄바꿈으로 구분) 한 번에 가져옵니다. 다른 탭의 이미지를 끌어다 놓거나, 라이브러리 화면에서 `Ctrl+V`로 링크를 붙여넣어도 됩니다.
  - **핀터레스트 핀** (`pinterest.com/pin/…`, `pin.it/…`): 원본 해상도 이미지를 가져옵니다.
  - **핀터레스트 보드/프로필** (`pinterest.com/사용자/보드/`): 공개 보드의 RSS에서 핀 목록을 가져옵니다.
  - **일반 웹페이지**: og:image, 본문 이미지, srcset(가장 큰 해상도), lazy-load 이미지를 후보로 보여줍니다.
  - **이미지 직접 링크**
- 후보 중 원하는 이미지를 고른 뒤 **키워드 태그**, **케이스**, **유형(이미지/로고)**, 메모를 지정해 저장합니다.
- 같은 이미지가 이미 있으면 새로 만들지 않고 태그만 합치며, 누가 언제 추가했는지 알려줍니다([중복 이미지](#중복-이미지)).
- `AI 태그 제안 받기`를 누르면 Claude가 이미지를 보고 **분야 / 대상 / 요소 / 소재·기법 / 컬러 / 무드** 축별로 1~2개씩 태그를 제안합니다. 바로 저장되지 않고 칩으로 보이며, 눌러서 채택하거나 ×로 뺍니다. 라이브러리에 이미 있는 태그를 우선 재사용하고, 같은 뜻이면 기존 표기(대소문자·띄어쓰기)를 씁니다. `pinterest`, `jpg`, `www`, 숫자만 있는 말, 한 글자 단어 같은 검색에 쓸모없는 태그는 걸러냅니다. API 키가 없으면 추측해서 붙이지 않고 'AI 연결 후 사용 가능' 안내만 보여줍니다. 레퍼런스 상세에서도 같은 제안을 받을 수 있습니다.

### 2. 검색·정렬 — `레퍼런스` 탭

- 검색 문법: `조형물 야간조명`(공백 구분), `#네온사인`(태그와 정확히 일치), `"포토 존"`(구문), `-로고`(제외).
- 매칭 방식은 **하나라도**(OR, 많이 맞을수록 위로)와 **모두**(AND) 중에서 고릅니다. 정렬 기준은 관련도, 최신, 오래된 순, 제목, 가로→세로 비율입니다.
- **태그별 그룹** 보기에서 검색 결과가 어떻게 묶이는지 미리 확인할 수 있습니다. 문서를 자동으로 만들 때도 같은 규칙을 씁니다.
- 여러 개를 선택(`Ctrl`/`Shift`+클릭)해 태그 추가·제거, 케이스 지정, 로고 전환, 삭제, 선택 항목으로 문서 만들기를 한 번에 할 수 있습니다.
- 사이드바의 태그 메뉴(⋯)에서 태그 이름을 바꾸거나 다른 태그와 병합할 수 있습니다.
- **태그 관리**(사이드바 `태그 → 관리`, `#/tags`): 태그별 사용 횟수(레퍼런스·케이스), 이름 변경(이미 있는 이름이면 합치기), 삭제, 여러 개를 골라 **동의어로 합치기**. `정리 추천`에서 대소문자·띄어쓰기만 다른 태그와 쓸모없는 태그를 한 번에 정리할 수 있습니다.

### 3. 케이스 — `케이스` 탭

하나의 사례(경기장, 매장, 브랜드 등)를 묶는 단위입니다. 케이스명, 서브타이틀, 강조 라인(예: `스폰서 : Allianz AG (보험/금융) / 소유: Allianz AG`), 설명, 태그를 관리합니다. `AI로 설명 채우기`로 소속 이미지를 분석해 빈 칸을 채울 수 있습니다. 유형을 '로고'로 지정한 레퍼런스는 케이스 페이지의 **로고 패널**(라벨 칩 + 로고)에 배치됩니다.

### 4. 문서 자동 생성 — `키워드로 문서 만들기`

키워드를 넣으면 오른쪽에 **그룹 미리보기**와 **페이지 미리보기**가 바로 나타납니다.

- **페이지 구성 기준**
  - **케이스별**: 케이스마다 케이스 스터디 페이지를 만들고, 케이스에 속하지 않은 레퍼런스는 태그로 묶습니다.
  - **태그별**: 검색어가 여러 개면 검색어별로 묶습니다. 하나면 결과 안에서 자주 쓰인 다른 태그로 나눕니다. 이미지가 적은 그룹은 매칭된 검색어 그룹이나 `기타`로 합칩니다.
  - **묶지 않음**
- 그룹 이름을 고치거나 체크를 해제해 빼고 만들 수 있습니다.
- 이미지 배치 방식, 페이지당 최대 이미지 수(넘으면 균등 분할: 11장 → 6+5), 페이지 크기(A4 가로·세로, A3, 16:9), 하단 양식, 타이포 프리셋, 표지, 간지를 설정합니다.
- `생성 후 AI로 작성`을 켜면 편집기가 열린 직후 모든 페이지의 빈 칸(타이틀·설명·캡션)을 채웁니다.

| 설정 | 설명 |
| --- | --- |
| 방향 | **가로 줄**(기본): 같은 줄의 높이를 맞추고 각 줄이 폭을 채움 · **세로 열**: 메이슨리, 같은 열의 폭을 맞춤 · **격자**: N단 균등 · **모자이크**: 비율에 맞춰 크고 작은 칸으로 분할(`섞기`로 다른 배열) · **보고서형**: 왼쪽 1단에 쌓고 나머지는 모자이크 |

**기본 더미 콘텐츠**: 새 템플릿 페이지(레퍼런스·케이스·간지)는 **Lorem Ipsum** 텍스트와 **회색 박스** 이미지 자리로 채워집니다. 회색 박스를 더블클릭하면 라이브러리 이미지로 바꿀 수 있습니다. `이미지 추가 → 자동 레이아웃에 추가`는 회색 박스부터 순서대로 채웁니다. 텍스트 도구로 만든 상자도 Lorem Ipsum으로 시작하며, 편집을 시작하면 전체가 선택되어 바로 덮어쓸 수 있습니다. AI는 Lorem Ipsum을 빈 칸으로 보고 채웁니다. 불러오지 못한 이미지도 회색 박스로 표시되며, PDF·PPTX·HTML로 내보낼 때도 같습니다.

모든 좌표는 **pt 단위**이므로 인쇄나 PPTX로 옮겨도 크기가 그대로 유지됩니다. 편집 내용은 자동 저장되고 팀원과 동기화됩니다.

## AI (Claude)

- `AI 글쓰기`: 현재 페이지의 이미지(최대 12장)와 태그·제목·메모, 케이스 정보, 검색 키워드를 근거로 **타이틀·서브타이틀·강조 라인·설명·섹션 라벨·이미지별 캡션**을 씁니다.
  - **관점**: `디자인`(형태·컬러·소재·타이포·공간 연출과 시각적 의도) / `기획`(목적·타깃·전략·경험 설계·기대 효과) / `팩트`(확인 가능한 정보만, 해석·평가 없이).
  - **문체**: 기본은 `보고체` — 명사형 종결(~구성. ~강조. ~전달. ~표현. ~상징. ~의미.), 한 문장에 정보 하나, 추측 표현 금지, 수식 형용사 최소화, 확인할 수 없는 수치·연도·사실은 쓰지 않음. `서술체`도 고를 수 있습니다.
  - 고른 관점·문체는 **문서마다 저장**되어 다음에 열 때도 그대로 쓰입니다(문서 양식 패널에서도 변경, 팀 기본 설정으로 새 문서의 기본값 지정).
  - 항목마다 `다시 쓰기`로 그 칸만 새로 쓰고, 오른쪽 **미리보기**로 페이지에 들어갈 모습을 확인한 뒤 체크한 항목만 적용합니다. 추가 요청(예: "더 짧게")도 넣을 수 있습니다.
- `전체 AI 작성`: 모든 페이지의 **비어 있거나 Lorem Ipsum인 칸만** 채웁니다. `Ctrl+Z` 한 번으로 되돌릴 수 있습니다.
- `AI 태그 제안`: [레퍼런스 추가](#1-레퍼런스-추가--레퍼런스-추가) 참고.
- 모델은 작업별로 나눠 씁니다. 글쓰기는 `CLAUDE_WRITING_MODEL`(기본 `claude-opus-5-5`), 태그 제안처럼 가벼운 작업은 `CLAUDE_TAG_MODEL`(기본 `claude-haiku-4-5`). 응답은 구조화 출력(JSON 스키마)으로 받고, 이미지는 서버가 받아 base64로 전달하므로 핫링크가 막힌 이미지도 분석합니다. 지원되는 모델에서는 요청 거절에 대비한 서버 측 폴백(`fallbacks: "default"`)을 켭니다.
- API 키가 없으면 글쓰기는 태그·제목을 조합한 **규칙 기반 초안**(보고체)으로, 태그 제안은 'AI 연결 후 사용 가능' 안내만 보여줍니다.

## 의견 보내기

- 화면 오른쪽 아래 `의견 보내기` 버튼(편집기에서는 프로필 메뉴)으로 **오류 신고 / 개선 요청 / 기타**를 보냅니다. 스크린샷은 선택이며 1~3장, 장당 5MB 이하(PNG·JPG·WebP·GIF)로 파일 선택·끌어놓기·`Ctrl+V` 붙여넣기가 됩니다.
- 보낸 사람 계정 메일, 현재 페이지 주소(인증·초대 토큰은 가림), 브라우저·OS·화면 크기, 보낸 시각이 자동으로 함께 기록됩니다.
- 내용은 **DB에 먼저 저장**한 뒤 `FEEDBACK_EMAIL`로 메일을 보냅니다(기존 SMTP 설정 사용, 스크린샷 첨부). 메일이 실패하거나 SMTP가 없어도 내용은 남습니다.
- 관리자(`ADMIN_EMAILS`, 비우면 `FEEDBACK_EMAIL`과 같은 **메일 인증된** 계정)는 프로필 메뉴 → `받은 의견 (관리자)`(`#/admin/feedback`)에서 목록·스크린샷을 보고 처리 완료로 표시하거나 실패한 메일을 다시 보낼 수 있습니다.
- 스팸 방지: 로그인한 사용자만 보낼 수 있고, 사용자당 **한 시간 5회 · 하루 20회**로 제한합니다. 첨부 파일은 확장자가 아니라 파일 앞부분(매직 바이트)으로 실제 이미지인지 검사합니다.

## 보안

| 영역 | 적용 내용 |
| --- | --- |
| 비밀번호 | scrypt(N=2^15) 해시 + 개별 솔트. 10자 이상, 흔한 비밀번호·메일 포함 거절. 로그인 실패 시 계정 여부를 드러내지 않음 |
| 무차별 대입 방지 | IP·계정별 요청 제한(로그인 15분 10회 등). 연속 실패 시 계정 잠금(5회 1분 → 10회 5분 → 15회 30분). 초대 코드는 비밀번호 10회 오류 시 잠금 |
| 세션 | 서버 저장 세션(토큰은 SHA-256 해시로만 저장). `HttpOnly`, `SameSite=Lax`, HTTPS에서는 `Secure` + `__Host-` 쿠키. '로그인 상태 유지'를 끄면 브라우저 세션 쿠키 + 서버 12시간 무활동/최대 1일, 켜면 비활성 14일 / 최대 30일 만료, 로그인 시 새 토큰 발급, 비밀번호 변경·재설정 시 다른 세션 모두 종료. 로그아웃·만료·팀에서 내보낸 사용자의 실시간 연결도 끊음 |
| 메일 토큰 | 인증(24시간)·재설정(1시간)·초대(7일) 모두 1회용, 해시로 저장. 가입 여부를 응답으로 드러내지 않음 |
| CSRF | 모든 변경 요청에 사용자 지정 헤더 필수 + `Origin`/`Sec-Fetch-Site` 검사(`APP_URL`과 일치해야 함) |
| 권한 | 모든 API에서 팀 멤버십과 역할을 서버가 검사. 다른 팀 데이터는 ID를 알아도 접근 불가(404) |
| 응답 헤더 | CSP(`script-src 'self'`, `frame-ancestors 'none'`), HSTS(HTTPS), `X-Frame-Options: DENY`, `nosniff`, Referrer-Policy, Permissions-Policy, API 응답 `no-store` |
| 소셜 로그인 | OAuth 2.0 authorization code + `state` 검증(10분, 1회용 쿠키). 제공자가 **인증한 메일**일 때만 기존 계정과 자동 연결 |
| 외부 요청 | 스크랩·이미지 프록시는 사설망·로컬 주소 차단(DNS 확인 후 IP 검사, 리다이렉트마다 재검사), 크기·시간 제한 (SSRF 방지) |
| 의견 보내기 | 로그인 사용자만, 사용자당 1시간 5회·하루 20회. 스크린샷은 매직 바이트로 형식 확인·파일 이름 정리, 관리자 화면에서도 `nosniff`·`sandbox` CSP 로 제공. 관리자는 메일 인증된 `ADMIN_EMAILS` 계정만 |
| 기타 | 요청 본문 10MB 제한(의견 보내기만 로그인·횟수 확인 뒤 24MB), 느린 요청 타임아웃, 내부 오류 내용 비노출, 보안 이벤트(로그인 실패·잠금·비밀번호 변경 등) 기록, DB 파일 권한 600·삭제 데이터 덮어쓰기 |

## 웹 서비스로 배포하기

### Render (추천 — 서버 관리 없이)

저장소 루트의 [`render.yaml`](render.yaml)(Blueprint)로 Render에 바로 배포할 수 있습니다. Node 22 런타임, Starter 인스턴스, 영구 디스크(`/var/data`)에 SQLite 저장, HTTPS 자동. Render 대시보드 → **New + → Blueprint** → 이 저장소 선택 → 비밀값 입력 → Apply.
입력해야 할 환경변수와 각 값의 의미, 소셜 로그인 콜백 주소, 백업, 문제 해결은 **[DEPLOY.md](DEPLOY.md)** 에 정리했습니다.

### 직접 서버 (Docker)

외부에 공개할 때는 **반드시 HTTPS**로 서비스하세요. 가장 간단한 방법은 동봉된 Docker 구성입니다(Caddy가 인증서를 자동 발급).

```bash
cp .env.example .env
#  APP_URL=https://refboard.example.com
#  SMTP_HOST=… SMTP_USER=… SMTP_PASS=… MAIL_FROM=…   (가입 인증 메일용, 사실상 필수)
#  SIGNUP_EMAIL_DOMAINS=회사도메인.com                  (권장: 회사 메일만 가입)
#  ANTHROPIC_API_KEY=…, KAKAO_* / NAVER_* (선택)
#  Caddyfile 의 refboard.example.com 을 실제 도메인으로 변경
docker compose up -d --build
```

- 앱 컨테이너는 root가 아닌 사용자로, 읽기 전용 파일 시스템·권한 최소화(`cap_drop: ALL`, `no-new-privileges`)로 실행되고 외부 포트를 직접 열지 않습니다. 데이터는 `refboard-data` 볼륨(`/data`)에 저장됩니다.
- Docker 없이 직접 실행할 때: `npm ci && npm run build && NODE_ENV=production npm start`. Nginx 등 프록시 뒤에 두고 `TRUST_PROXY=1`을 설정하세요. 실시간 동기화(SSE)를 위해 프록시 버퍼링을 끄세요(Nginx: `proxy_buffering off;`).
- **백업**: `npm run backup`(Docker: `docker compose exec app node --import tsx scripts/backup.ts`)으로 `data/backups/`에 스냅샷을 만듭니다. cron 등으로 매일 실행하고 서버 밖으로 복사해 두세요. 데이터는 이 SQLite 파일 하나뿐입니다.
- 서버 한 대(프로세스 하나)로 실행하는 구조입니다. 실시간 동기화와 요청 제한이 메모리에 있으므로 여러 대로 늘리려면 Redis 등 공유 저장소가 필요합니다. 수십 명 규모 팀은 한 대로 충분합니다.
- 헬스 체크: `GET /api/health`.

## 소셜 로그인 설정 (카카오 · 네이버)

두 곳 모두 **가능합니다.** 각 개발자 센터에 앱을 등록하고 키를 `.env`에 넣은 뒤 서버를 다시 시작하면 로그인 화면에 버튼이 나타납니다.

**카카오** — [Kakao Developers](https://developers.kakao.com)
1. 내 애플리케이션 → 애플리케이션 추가
2. 앱 키의 **REST API 키** → `KAKAO_CLIENT_ID`
3. 카카오 로그인 활성화, Redirect URI에 `{APP_URL}/api/auth/oauth/kakao/callback` 등록 (예: `https://refboard.example.com/api/auth/oauth/kakao/callback`, 로컬 테스트는 `http://127.0.0.1:5178/api/auth/oauth/kakao/callback`)
4. 보안 → Client Secret 발급·사용 설정 → `KAKAO_CLIENT_SECRET` (권장)
5. 동의항목: 닉네임(필수), 카카오계정(이메일)(선택)
   - 이메일 동의항목은 **비즈 앱 전환**(사업자 정보 등록)이 필요할 수 있습니다. 이메일 없이도 로그인은 되며, 이 경우 메일 계정과 자동 연결되지 않고 별도 계정이 됩니다(내 계정에서 직접 연결 가능).

**네이버** — [NAVER Developers](https://developers.naver.com)
1. Application → 애플리케이션 등록 → 사용 API: **네이버 로그인**
2. 제공 정보: 이름(또는 별명), 이메일 주소
3. 서비스 URL `{APP_URL}`, Callback URL `{APP_URL}/api/auth/oauth/naver/callback`
4. Client ID → `NAVER_CLIENT_ID`, Client Secret → `NAVER_CLIENT_SECRET`
   - 등록 직후에는 **개발 중** 상태라 `멤버관리`에 등록한 계정만 로그인됩니다. 팀원 모두 쓰려면 **검수 요청**(서비스 적용)이 필요합니다.
   - 네이버가 주는 메일 주소는 `@naver.com`일 때만 인증된 메일로 보고 기존 계정과 자동 연결합니다(다른 도메인은 본인 확인이 보장되지 않으므로).

> 이 개발 환경에서는 카카오·네이버 서버에 접속할 수 없어 실제 로그인은 확인하지 못했고, 제공자 응답을 흉내 낸 테스트로 흐름(인가 코드 교환, 사용자 정보 해석, state 검증, 계정 연결 규칙)을 검증했습니다. 키를 넣은 뒤 실제 계정으로 한 번 확인해 보세요.

## 알아둘 점

- 이미지는 **링크로만** 연결합니다. 원본이 삭제되거나 주소가 바뀌면 이미지가 보이지 않습니다. 그럴 때는 레퍼런스 상세에서 주소를 교체하세요. 핫링크가 막힌 이미지는 자동으로 서버 프록시(`/api/proxy`, 로그인 필요)를 거쳐 표시합니다.
- 핀터레스트는 **공개** 핀·보드만 가져올 수 있습니다. 보드 RSS는 최근 핀 위주로 제공되므로 오래된 핀은 개별 핀 링크로 추가하세요.
- 웹폰트(Pretendard, Poppins, Noto Sans KR 등)는 CDN에서 불러옵니다. PPTX를 여는 PC에 해당 폰트가 없으면 대체 폰트로 보입니다.
- 내보낸 HTML·PPTX·PDF 파일은 로그인 없이 열리므로, 외부 공유는 파일 단위로 관리하세요.
